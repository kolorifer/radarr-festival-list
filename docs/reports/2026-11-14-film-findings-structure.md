# Film findings structure correction

The v4 schema described six findings as an array, but the local parser did not enforce its minimum length and neither the schema nor the local parser prevented duplicate aspects. A receipt-backed v4 `snapshot_film_findings` refusal therefore identifies a failed six-aspect structural condition; it does not reveal the discarded answer or whether it was short or duplicated an aspect.

The v5 contract uses a closed object with six required named findings and aspect-specific field choices. It preserves the v4 semantic and citation guards, unknown and unresolved outcomes, existing output limits, and the earlier v1–v4 requests. A reviewed one-child successor must bind the exact v4 diagnostic, receipt, request, history and debit and retain the full earlier ancestry. It may use the same still-current verified projection or a genuinely refreshed, independently reviewed projection of the same case and identities. No prior answer is reconstructed.

The corrected report records the immediate structural refusal. Earlier completed reports remain in the retained history and are not reproduced in that report. Finding explanations remain subject to the existing concise-text and safety checks. No live authority or provider call is created by the code change.

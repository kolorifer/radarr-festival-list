# Supervised synthetic authorization

## Agreed scope

Replace the accepted command's unconditional HTTP refusal only for its two
explicit fixed-synthetic slots. Preserve the published PR147 and PR148 heads,
all request/project/model/expiry and durable full-cent reservations, no retries,
and refusal of generic unattended or movie calls. Repair the three independent
review findings before acceptance: caller-controlled expiry, unproven root
transaction, and evidence ACL privacy. No service or production deployment.

## Implementation

The interactive command issues opaque process-local, single-endpoint permits.
Each permit binds exact request bytes, project, credential object, selected
owner-private evidence bytes and enrollment. The live boundary verifies the
held root write transaction against its actual descriptor and durable records;
invented event lists, exited transactions and unprompted credentials refuse.
The prompt is no-echo and TTY-only. Each boundary recheck requires real wall
clock and elapsed monotonic time, with caller time permitted only to tighten
expiry; backward wall movement refuses.

Evidence reads use the existing manual/coordinator descriptor guard algorithms
in a self-contained installed module. Every ancestor is checked for ownership,
mode, symlink substitution and ACL; final directory/file are owner-only. Darwin
allows only deny ACL entries or proven absence, Linux requires proven ACL
absence. File bytes/identity and metadata are rechecked. This does not provide
isolation from a malicious process running as the same OS owner.

Count and generation each retain a full one-cent reservation, including uncertain
failures. Only the fixed synthetic request and its count projection can receive
permits. Tokens expire with the command context and cannot enable generic
movie/research paths. No new service, worker, claim, credentials or API call.

## Validation and remaining limits

78 focused command, credit, bound-send and Responses tests passed on the available
system Python 3.9, with terminal and HTTP I/O replaced by fixtures. New regressions
cover actual expiry with a frozen caller clock, wall rollback, missing/forged/
expired transactions, missing prompt provenance and ACL/ancestor refusal.
Supported Python 3.12/3.13 exact-head CI and independent installed-closure review
are required before acceptance. Retained local 3.12/3.13 runtimes are unavailable;
no repair or download was attempted.

Actual count-fee and coverage evidence remains absent. No real eligible evidence
selection, key provisioning, API request, billing change or production activation
occurred. Fixture results establish code behavior, not real account readiness.

Independent installed review observed an inter-read ctime change with identical
bytes, inode, size and mtime; its cause remains unknown. Persistent selection
therefore retains the prior dev/inode/size/mtime plus exact-byte binding. Every
individual read still checks ctime before/after, and every revalidation checks
current ownership, mode, link count, ACL and ancestor safety. This does not detect
all same-owner changes restored between reads (including restored mtime); it is
not swap-and-restore protection. Two regressions cover both boundaries.

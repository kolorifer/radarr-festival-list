# Bound source companion for supervised historical review

## Completed brief

Extend the existing manual prepare/complete flow with an optional private normalized collector/observer observation. Freeze its original bytes, bind its hash alongside the retained historical case, validate their selected case, version, facts and underlying event time, and put only useful minimized observations into the actual model input and report. Preserve historical catalogue clocks, expiry, unknown provenance and all production refusal and approval boundaries. No source connection, provider call, spending, deployment or new worker is part of this change.

## Implementation and state

`--prepare --companion` reads the bounded private companion through the existing storage guard. The new parser accepts the completed collector/observer observation shape, checks matching source identity claims and ordered observation clocks, validates review links, and projects pending state, observation times, opaque prior-occurrence reviews and explicit limitations. It excludes raw case, version, event and delivery identifiers. Source authenticity remains an external operator check; no supplied verified flag is accepted. Historical event/delivery bindings remain unchanged.

The companion is frozen as `companion.json`; its exact hash participates in selection and assessment binding. Completion reconstructs the request from both frozen inputs and rejects changed bytes, unexpected companions, replay and missing source citations. The report carries the same minimized observation. An absent companion preserves the previous request and report behavior byte-for-byte. Pending absence is explicitly limited to the observed instant and is not delivery or acknowledgement proof. Source observation time never refreshes the historical movie evidence.

## Validation and independent review

64 focused tests passed on each Python 3.12 and 3.13, including synthetic pairing mismatches, frozen-source tampering, replay, source citations, opaque review links, expiry preservation and a network tripwire. Earlier accepted real requests were reconstructed byte-for-byte without replay. The exact retained historical input and separately inspected normalized observation were prepared together using real private-storage guards, then an actual coordinator-authored supplied assessment was validated into a report containing the bound source observation. Private input, source, response and report bytes are excluded from the repository. Source authenticity and chat authorship require independent external verification; local hashes do not prove them.

The same independent reviewer accepted the focused code and historical compatibility. The reviewer also independently accepted the actual paired input, frozen request, reply, report and History pins; supported exact-head full CI is required before merge. No runtime installation or production activation is performed. The unrelated active implementation task is preserved; this scoped completed brief/report records the state without republishing unrelated historical project material.

## Remaining operational gap

The manual interface now binds both evidence sources, but the operational source reader remains fixed to one selected case and version. A repeatable explicit case-selection/read path with applicable prior-decision coverage is the next concrete read-only workflow gap. It is separate from live provider activation, spending, identity correction and acquisition, none of which this change enables.

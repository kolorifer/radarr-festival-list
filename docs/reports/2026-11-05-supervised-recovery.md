# One-time supervised synthetic recovery

`recover-once --previous-evidence OLD --evidence NEW` validates the retained
five-record enrollment/consumed-slot shape, original pinned storage, empty first
attempt, second reserved/attempted request and matching three-cent credit debit.
It appends a start record binding that history, evidence, project and fixed slot3
request; creates one private attempt directory; then appends its inode grant.
Any interruption after the start is terminal. Existing enrollment and records
remain unchanged. This command neither prompts for a key nor invokes the API.

Only `run --slot 3` with that selected fresh evidence can use the grant. The
six-cent cumulative ceiling is derived from the active, prompted, root-locked
session at reservation and HTTP checks. The original five-cent default remains
for other operations. Both consumed slots, the unknown debit, fixed request,
short send authority, secret validation and no-retry behavior are preserved.

Validation: focused invented-state and actual installed-module PTY tests cover
conservation, unknown completion, shared total, duplicate/restart/slot4 refusal,
interrupted extension, changed evidence/project/storage and invalid input.
Independent review and supported exact-head CI are required before acceptance.
No actual recovery, evidence refresh, credential access or provider call is part
of this implementation verification. A distinct private runtime rehearsal is a
separate handoff step; no existing runtime or operational state is overwritten.

Scope: three runtime modules, manifest and focused tests. The unrelated active
cleanup brief is preserved. No scoring, movie decisions, producer, dispatcher,
service, production activation or schedule changes.

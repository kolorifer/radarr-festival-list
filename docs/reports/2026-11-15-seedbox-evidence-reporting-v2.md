## Executable one-case correction

With the existing worker stopped, main can call
`automation.seedbox_evidence.correction_proposal(queue, old_preparation)` offline.
It verifies the old original/manifest, assessment/request/answer/HTML and separate
review/request/receipt/attempt chain. It requires a rejected review, no send,
non-imported original case, two completed consumed requests and a material change
from rederiving the same source bytes. It returns a hash-bound proposal; it does
not acquire, spend, claim a fresh observation or authorize execution by itself.
`record_correction(queue, old_preparation)` optionally retains that proposal once.

After reviewing that exact proposal, the installed verified bootstrap supports:

```
python -I -B BOOTSTRAP MANIFEST MANIFEST_SHA correct CONFIG CONFIG_SHA OLD_PREPARATION PROPOSAL_SHA
```

This takes the existing singleton lock and atomically appends exactly one distinct
preparation with the explicit correction binding. Repetition or a correction of
a correction refuses. Normal acquisition must obtain fresh observations for the
same selected listing, original target and catalogue; semantic source facts must
match the material corrected derivation. Changes refuse before provider use.
The same ledger/policy reserves new unique assessment/review requests, retaining
all prior debits and receipts. Interrupted/uncertain new requests remain consumed;
only next unsent stages may proceed. No automatic correction loop, reset, refund,
re-enrollment, target replacement or old-request retry exists.

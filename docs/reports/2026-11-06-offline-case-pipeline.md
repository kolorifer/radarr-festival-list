# Finite offline case pipeline — 2026-11-06

## Connection and boundary

The existing new-case handoff accepted supplied answers; the fixed HTTPS path
accepts only the exact manual synthetic-credit request. A generic movie request
cannot use that authority. This change leaves that live gate unchanged and adds
a disabled-by-default offline connection for exactly the canonical invented
synthetic occurrence 165 in an empty private History. This fixture restriction
is a test boundary, not a film-specific production rule. Other captured records,
existing histories, callbacks, transport objects and prebuilt results are refused.

The connection reuses admission, minimized handoff projection, the existing Nano
request policy, output schema and result validator. It records a durable
simulated-send start, invokes an internally constructed memory-only transport
once, validates locally stamped request/project/path correlation and parses the
complete response envelope. An opaque in-process completion context binds the
same history, handoff, decoded answer and retained simulated response. Supplied
answers cannot finish a marked uncertain attempt. A completion in the preparation
gap is rejected under the same lock that appends the simulated-send marker.

The status/header/framing/body reader is extracted unchanged from fixed HTTPS.
The simulated path uses http.client POST serialization and HTTP response parsing
against a static memory socket; the same reader enforces the generic 32 KiB
response bound. No live authorization, URL, credential, callback, retry or model
fallback was introduced. The existing static HTTPResult fixture API remains
available to its old callers, but is not accepted by this new connection.

The result is the existing qualified, unsent simulation draft. It truthfully
retains generation_invoked=false and provenance_verified=false, and separately
records simulated_transport_invoked=true. Correlation is local fixture evidence,
not genuine model inference, provider authentication or billing evidence. The
existing delivery fixture uses an isolated Digest and fake sender; even its
successful transport acknowledgement is marked simulated and does not establish
recipient ingestion, identity approval or acquisition approval.

# Captured evidence successor and private report

**Scope:** An explicitly main-reviewed, same-occurrence material-evidence
successor after a captured `unsupported_candidate` completion rejection. Preserve
the original captured event, request, receipt, failure, prior attempts and
reservations. No actual account, credential, provider, case or production
operation was performed by this implementation.

## Evidence and request

The prior packet can contain candidate-free catalogue title/year observations;
they remain unchanged and are not treated as candidate support. A pure preflight
adds two separate scoped evidence rows only when the exact normalized catalogue
crosswalk and source occurrence assertion bind the same IMDb/TMDb pair. Main
must independently verify and attest derivation from the separately retained
original artifacts. Hashes establish byte identity, not source truth. The
attestation binds both complete origin/time/expiry pins, original and normalized
artifact digests, the occurrence and the local-report context digest. Missing,
stale, forged, conflicting or unbound inputs refuse before a send.

A versioned `minimized_evidence` prepared record selects a deterministic request
serializer at preparation, grant, completion and draft recomputation. It replaces
all evidence free text with fixed labels and exposes explicit attested citation
aliases. The minimized prompt/schema require exactly the two reviewed citations
for a supported candidate, no alternatives, and permit unresolved/blocked results.
Film identity is a review proposal; physical edition, measured media runtime,
current queue and identity/acquisition approvals remain separate. Legacy prepared
requests retain their previous serializer.

The existing material-change replay gate is retained: both scoped material and
prepared-time disclosure material must differ; clock-only changes do not count.
A new proof binds the latest prior unsupported-candidate terminal, its receipt,
prior rejected completion, unchanged original packet and root/case/credit
prefixes. Existing locks, credits, authorization and one-send CLI remain in use;
the enriched attempt is not refreshable or replayable. A partial preparation,
allocation, send or report write is retained as a consumed/uncertain state and
is never automatically retried.

## Private report

The unissued operation entrypoint holds the existing root/case and private path
guards, checks reviewed original/normalized evidence and context, prepares and
authorizes the single material successor, calls the existing CLI once, then
checks the exact durable case result, root completion and transport receipt.
It generates an owner-private HTML file exclusively through the held report
parent descriptor and reports success only after all guard cleanup completes.
The local-only report includes the original tracker link/release/NFO, a compact
source-versus-catalogue comparison and the accepted structured assessment with
role-labelled citations and limitations. Untrusted dynamic values are HTML
escaped. Unknown values remain missing, cast subsets/reordering are not treated
as conflicts, and source/catalogue durations are not measured media duration.

The main supervisor must independently verify the supplied original source and
catalogue bytes, their derivations, local facts/context and exact owner scope.
The entrypoint is an unissued template; a hash or freely supplied attestation is
not independently authenticated source truth. Tracker/NFO/account material is
not added to the minimized provider view or emitted to stdout.

## Validation and limitations

An isolated public-code checkout passed 28 focused invented-data tests in
30.107 seconds. Coverage includes exact evidence/clock/digest failures,
candidate-free legacy rows, minimized prompt and structured eligibility,
confirmed non-secret envelope shape, conflict/refusal cases, unresolved report,
hostile HTML, exact installed CLI through the same operation entrypoint, one
simulated send and restart refusal. Bad capture, expired evidence, invalid local
context and wrong slot refuse without journal, credential or output writes. A
post-write cleanup failure produces no success message. Installed tests use
invented file, credential and HTTP adapters; they do not establish actual
Keychain, native host guard, source authenticity or provider success.

A Documents-path local fixture hit the existing `supervised_evidence_changed_read_ctime`
guard before its intended assertion; this was not counted as a passing test and
no guard was weakened. The later isolated tests did not use actual case/state.
Independent exact-head review, supported Python 3.12/3.13 CI and repository
integration are required. Main owns any issued operation; no extra user approval
is implied or requested by this report.

# Contextual film assessment and prose retention

## Agreed scope

Correct the explanation filter and underlying evidence-assessment request together,
using public code and invented fixtures only. Preserve exact old request contracts,
all prior attempts and reservations, and the existing one-case pipeline. No live
provider, credential, private-case, collector, deployment or production operation.
The unrelated cleanup task in CODEX_TASK.md remains assigned and untouched.

## Implementation

`film_context_v8` retains the established transport format name but changes the
request/schema and requires its own exact owner/main authorization. A blocker
must include concise `support_considered` and `material_conflict` explanations.
Instructions explicitly distinguish producer/collector labels, festival/theatrical
years, rounded measurements, actual identifier conflicts and unrelated listing
titles. Matching IDs alone remain insufficient; a candidate is advisory, never
identity, edition or download approval. No score, threshold or forced-positive
rule was added. Local validators bind evidence/shape; they cannot prove that the
model's prose is substantively correct. Human review remains necessary.

The v8-only prose policy permits ordinary labels, questions, and bounded standalone
comparison forms: festival/theatrical, IMDb/TMDb, and/or, and two four-digit years
(with optional spaces around the slash). Other slash forms, path segments, URLs,
credential syntax, markup, controls and long opaque strings remain refused.
Whole unsafe fields are withheld, without logging originals or internal reasoning.
This finite filter is not a universal secret detector. Older v1–v7 request bytes,
text behavior, hashes and parser limits remain unchanged. Original and retained
reply hashes remain distinct. Reports show model-provided blocker explanations
and preserve the actual earlier rationale/uncertainty withholding states.

Rationale and uncertainty are limited to 300 characters each; each of up to six
blockers has two 160-character explanations. The invented maximal non-BMP answer
is 31,110 encoded bytes, below the unchanged 32,768-byte parser limit. This avoids
increasing transport or durable record limits.

## One deliberately issued child

The existing unissued snapshot wrapper accepts `context_reassessment` only with
`film_context_v8`, `snapshot_context_scope_v1`, and a main review binding its digest.
The proof kind is `snapshot_context_reassessment_v1`; exact proof keys are checked
by `snapshot_authorization.validate_context_reassessment`. It binds the previous
v7 start/grant/completion/report/retained-answer/receipt/attempt/credit/request,
prior status/candidate/prose handling, root prefix and new request hash. At least
one original v7 explanation must have been withheld for `path_or_url_syntax`.
The old report must be completed, unsent and receipt-correlated. The exact prior
request, authority and observation artifacts are revalidated. Same or freshly
attested observations must retain case, source identifiers, catalogue pair and
source location. New authorization cannot replay the old request.

Exactly one immediate child is allowed, including during execution-time lineage
revalidation. Every earlier attempt and reservation stays intact; failed or
uncertain sends remain consumed. No general retry, reset, automatic loop,
additional runner or alternative route was introduced. The existing 47-file
installation manifest is updated; no runtime is issued by this change.

## Validation and limits

Focused tests cover benign prose and forbidden disclosure, frozen v7 bytes,
required contextual explanations and instructions, wrong binding, true ID and
unrelated-title negatives. Installed tests use a complete invented receipt-backed
history, the actual unissued-wrapper template and fake HTTP sockets, with native
process/network tripwires, maximum-size unresolved/supported responses, retained
receipt/report verification, append-only history/credit checks and duplicate
refusal. A separate case covers uncertainty-only prior withholding.

These tests establish pipeline behavior, not live model quality or provider
acceptance of the new schema. The full repository suite and exact-head Python
3.12/3.13 CI are merge gates; independent review is required. No actual private
case, account state or provider output was inspected by this engineering task.

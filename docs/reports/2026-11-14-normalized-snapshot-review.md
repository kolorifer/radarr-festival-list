# Normalized snapshot review: scope and operator contract

This change adds a separately gated, one-case local review from a fresh,
authenticated collector snapshot and independently reviewed listing and
catalogue observations. It does not change captured-event admission, services,
schedules, production matching, notifications or acquisition. A normalized
snapshot does not establish original captured bytes, complete decision history,
physical edition or current queue status. A model's supported candidate remains
an unsent human-review proposal. Source and asserted IDs stay distinct, and ID
disagreements block a supported result. The producer's conflict remains visible.

The main supervisor must independently verify the collector snapshot, each
original source and catalogue observation, the exact source-to-case link and
catalogue IMDb/TMDb crosswalk. Byte hashes bind artifacts but do not authenticate
their origin. An attestation or file written by this code is not owner approval.
Only a trusted main-reviewed wrapper may enter the default-closed context. The
existing append-only root, credit reservations, no-replay checks and fixed
Keychain/HTTP/parser/receipt controls remain in use. A failure after an attempt
is reserved burns it; do not replay an uncertain send.

## Typed private inputs

All files are owner-private, individually pinned with absolute path and SHA-256.
The complete collector snapshot is the existing `/v1/investigations` export;
the selected case must be the unique eligible movie with the requested case ID
and version. Each clock is an actual observation time in Unix seconds; expiry
values are independently selected by the supervisor, not generated by this code.
At allocation there must be more than 180 seconds until the snapshot becomes one
hour old and until each evidence/authority expiry. Local report completion is
not time-bounded; a late result still fails closed and is not retried.

The normalized listing fact object has exactly these keys:

```
kind: selected_listing_facts_v1
case_id, version, observed_at, expires_at
 title, year, description_runtime_minutes, nfo_runtime_milliseconds,
 nfo_runtime_kind, cast, directors, imdb
```

`title` and `year` may be null; each list contains up to 20 names. NFO runtime is
an integer number of milliseconds or null. Its kind is exactly `container`,
`video`, `audio`, `subtitle`, `unknown` or `absent`; unknown/absent require null.
This is an uploader-reported observation, not a measurement of the user's media.
The independently normalized catalogue object has exactly:

```
kind: catalogue_facts_v1
observed_at, expires_at, title, theatrical_year, festival_years,
runtime_minutes, cast, directors, imdb, tmdb
```

Unestablished scalar values are null and unestablished lists are empty. Years are
integers; runtime values are integer minutes. All public textual fields must pass
the existing safe-text filter. Source link, release name, NFO text, operational
case IDs and original private bytes are excluded from provider disclosure.

A separate private local-context JSON has exactly `tracker_url` (HTTPS),
`release_name`, and `nfo_text` (empty when unavailable). This context is bound to
main's review and remains local. The original listing and catalogue artifacts are
separate pinned files; the supervisor's exact review must explain their relation
to the normalized facts. The source observation and catalogue observation above
are not automatically authenticated merely by their pins.

The attestation object has exactly `kind` = `main_reviewed_normalized_case_v1`,
`snapshot_sha256`, `case_id`, `version`, `source_sha256`, `catalogue_sha256`,
`source_original_sha256`, `catalogue_original_sha256`,
`source_linkage_verified` = true, `catalogue_crosswalk_verified` = true,
`observed_at`, and `expires_at`. No absent provenance or event receipt is invented.

The owner scope object has exactly `kind` = `snapshot_assessment_scope_v1`,
`case_id`, `version`, `max_calls` = 1, `disclosure_allowed` = true, and
`production_allowed` = false. The main-review object has exactly `kind` =
`snapshot_main_review_v1`, `owner_scope_sha256`, `snapshot_sha256`,
`source_sha256`, `catalogue_sha256`, `source_original_sha256`,
`catalogue_original_sha256`, `local_context_sha256`, and
`provenance_reviewed` = true. These artifacts document trusted-main review;
they are not signatures or a substitute for the actual owner instruction.

The canonical authority record has exactly `kind` =
`trusted_main_normalized_snapshot_v1`, `owner_scope`, `main_review`,
`root_identity`, `root_prefix_sha256`, `root_count`, `project`,
`account_reference`, `output_dir`, `output_identity`, `snapshot`, `source`,
`catalogue`, `source_original`, `catalogue_original`, `local_context`,
`attestation`, `runtime_manifest_sha256`, `issued_at`, and `expires_at`.
Each named file pin is exactly an object with `path` and `sha256`; identities
are `[device, inode]`. The root prefix includes every existing reservation and
attempt. The output directory must already exist, be empty, owner-private and
match the exact pinned identity.

## Unissued wrapper

`automation/snapshot_review_UNISSUED.py` is inert until trusted main creates a
private exact copy with its sole `ISSUED = None` replaced by reviewed literals.
Its `ISSUED` object contains `runtime`, `runtime_files`, `python_sha256`,
`main_acceptance_path`, `authority`, `account_evidence`, `state`, `output_dir`,
`root_prefix_sha256` and `expected_slot`. The acceptance record contains
`decision` = `accepted_exact_normalized_snapshot_assessment`, `wrapper_sha256`
and the exact `issued_pins` object. Main must inspect and pin every input and
confirm current account/credit evidence before issuing this record. The wrapper
verifies the fixed private guard and all runtime hashes before importing runtime
modules. Invoke only the exact reviewed wrapper with the reviewed Python as
`-I -S -B`, followed by `--main-accepted-snapshot-review`. It allocates at most
one slot, runs at most one request and writes `movie-review.html` only after the
durable completion, sanitized answer and receipt agree. It prints success only
after private guards close successfully. No CLI or environment variable alone
can open the gate.

If report writing is interrupted after a confirmed completed send, trusted main
may re-enter the exact same reviewed authority and call `write_completed` for the
same slot after validating all retained records. This reads the existing receipt
and does not allocate or send again. It requires the original evidence, authority
and output identity to remain valid. If the source, receipt or delivery is
uncertain, retain the evidence and do not retry.

## Verification and limitations

Invented tests exercise projection, ID conflicts, timestamps, scope, forged proof,
private output identity and an isolated fake-HTTP receipt/report path. Integration
fixtures replace transport and selected native I/O; they do not establish source
origin, actual account state or live provider behavior. Full supported-version CI
and independent review are required before using an installed runtime. This
engineering change does not itself operate the live collector or provider.

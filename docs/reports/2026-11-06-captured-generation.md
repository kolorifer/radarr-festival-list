# Captured-occurrence connection — engineering record

The existing supplied-answer route had no transport-generation authority.
Its captured occurrence was intentionally incompatible with the historical
parent's null occurrence and fixed historical disclosure. The extension uses
a distinct `captured` grant inside the existing supervised session and parent;
it does not reinterpret historical or synthetic consent.

The installed entry points refuse unconditionally before private reads or
mutation. There is no environment, CLI or JSON switch to enable real use.
The consent does not select provenance. The existing session snapshots a
trusted in-process simulation marker before response I/O and checks its identity
at receipt binding and completion. The dormant genuine path records generation
only after fixed-transport request/project correlation; this is not a provider
signature, independent billing proof, chat ingestion or recipient receipt.
Invented tests mark their I/O explicitly and patch the closed activation
function and socket/native Keychain I/O; no actual
fresh-case grant, source authenticity, queue currentness, complete decision
coverage, identity/acquisition approval or delivery authority is established.

Exact canonical authority pins root prefix, account evidence, case directory
and journal identity, prepared handoff, captured packet/occurrence, full
reconciliation, final-only serialized request, expiry and one 3-cent debit.
Candidates and original citation validators remain supported. The historical
unresolved-only contract and existing supplied-answer request are unchanged.

Root and case transactions remain held through send and completion. Short
attempt/credit transactions retain their existing order. Case generation is
consumed before the root send marker; an interruption between those appends
cannot regain authority. The fixed transport's actual in-memory HTTP result,
reparsed answer and exact durable receipt establish a one-use completion
binding. A copied HTTP result, supplied answer, grant or durable receipt cannot
finish the case. Completion operates on the held transaction, never reacquires
its non-reentrant lock. All reports remain unsent. Simulated results explicitly retain
`generation_invoked=False`; only genuine receipt-correlated transport completion
can set it true. Ordinary supplied answers cannot select that provenance.

Validation during implementation: the first 7 connected tests plus 20 existing
new-case tests passed. Extended tests exposed a real pre-send staleness gap:
reconciliation alone does not include ordinary evidence expiry. The captured
route now also compares projected qualifications at preparation and send time.
The source hash manifest was refreshed for the unchanged 42-file closure.
The latest 15-test run passed 14, including installed-only completion, failure,
restart and default-closed tests. One test stopped at the existing macOS
`supervised_evidence_changed_read_ctime` guard before reaching its wire check;
the same lock test passed in an earlier implementation run. Earlier ctime
failures are retained, not bypassed or rerun to claim general reliability.
After the architect requested complete dormant genuine-generation semantics,
the revised 17-test run passed 15; two citation/binding tests stopped at the
same unchanged ctime guard. Both had passed in the previous run. Installed
completion/uncertainty/restart and provenance-switch refusal passed. No local
full-green claim is made; supported exact-head CI is the remaining full-suite
gate. Architect-selected `captured-final-v1` uses an explicit 25,000-token total
generation allowance including reasoning. At the unchanged Nano rates and
400,000-token input bound, the worst case is $0.03, within the existing 3-cent
reservation. This limit is bound through request, session, parent and parser;
the 8,192-byte answer bound, 120-second observation and one-send rules remain.
Old routes/defaults are unchanged. This avoids inheriting the previously
observed historical 4,096-token incomplete result, without guaranteeing future
completion or enabling an expensive fallback. Independent
review and exact supported full CI are required before acceptance.
No actual credential/source/account/provider access or deployment occurred.

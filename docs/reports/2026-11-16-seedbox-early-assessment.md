# Early assessment with an exact original receipt

## Agreed scope

A valid retained initial notification receipt must allow the assessment and its
separate reporting review to finish while the actor follows its ordinary retry
schedule. Delivery still requires the original notification to be complete and
quiescent. The writer uses public code and invented fixtures only; main owns
private inspection, worker deployment and the explicitly selected recovery.

## Implementation

A versioned ownership pin binds the single original reference, retained original
payload and actor job, normalized release metadata, actor database and selected
actor process/code topology. It is assessment evidence, not edit permission.
Existing complete-target checks remain at delivery. Missing initial receipts
wait locally; old generic failures need the explicit `assessment-recover` mode,
whose proof includes all old source starts, failures and consumed history. Their
historical GET phases remain unknown. No source interruption is silently retried.

A successful authenticated exact IMDb lookup with an empty `movie_results` array
is typed evidence of no movie mapping at that time. It retains original bytes,
lookup ID and clock, a false crosswalk flag and null catalogue identity. The model
request and private HTML state the observation, without claiming that no film
exists or inventing a candidate. Missing, malformed, multiple-result and API
error bodies refuse. Legacy request/report bytes are unchanged when this new
observation is absent. No title search or additional provider route is added.

After separate review the worker waits quietly for ordinary original completion.
A terminal handoff must link the collector delivery UUID to the unique latest
completed actor retry attempt, reconstruct its exact selection signature, and
preserve release metadata, assertions, evidence, original reference and review
boundaries. A terminal event already present at assessment is checked explicitly.
A tied latest attempt, unlinked expiry/attempt-limit fallback, changed identity,
new occurrence or unknown selected delivery refuses. A not-yet-collected normal
terminal outcome waits without source/model work. Initial exact webhook identity
is not established: the proof is for the same release/job and exact original
receipt, with normal retry-attempt transport lineage.

If needed, one automatic source-only handoff obtains the same listing/catalogue
facts. The original assessment snapshot, case version and observation clocks,
model answer, separate review, private report and card remain immutable. A new
wrapper generation clock supports the fresh source comparison only. The typed
handoff separately retains the actual terminal collector version/route (including
`review_only` / `retry_exhausted`) and full completed target. Ordinary eligible
case admission is not broadened. Changed facts stop rather than regenerate a
model response. Failed or interrupted handoff attempts remain consumed.

The final edit checks the actual terminal collector anchor and every later
selected/unknown delivery under the existing sender boundary, including the
already-complete/fresh-evidence path. It does not reopen the actor database inode
inside its writer transaction. Existing exact target, spool, process, code,
freshness, original lock and no-resend checks remain. A previously started send
returns its consumed status before inspecting a now-consumed original.

## Validation and handoff

Focused invented tests cover the real source/normalization, framed assessment,
separate review, quiet waiting, normal third retry, proof-bound source handoff and
single original edit; absent/error lookup distinctions; explicit old-history
recovery; changed facts, ownership, new occurrences and unlinked terminal UUIDs;
installed-only nonempty derivation/lineage and a retained failure. Existing
focused regression and legacy request/report compatibility checks are retained.
Exact candidate results, independent review and supported Python 3.12/3.13 CI
are recorded in the PR and parent checkpoint before merge.

No actor retry schedule, service, producer, budget, deployment or real source,
model or notification operation is performed by this repository change. Existing
uncertain notification attempts remain consumed. Main independently verifies
public blobs and the selective package before any worker-only deployment.
